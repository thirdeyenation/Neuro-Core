Neuro Core — Configuration reference

Every setting of the Neuro Core memory service lives in one bundled file, default_config.yaml, and can be overridden per project and per agent via the framework's plugin settings chain. This page gives key-level guidance for all 21 keys, mirroring docs/configuration.md. The Settings window exposes all 21 keys: five operator-level controls in Basic view, and every key grouped by territory under Advanced Settings. Changes apply to future operations after the Settings window is saved — already-stored memories and already-computed scores are not re-processed.

Lifecycle internals

Controls the two recurring maintenance passes: importance decay and episode grouping.

decay_enabled (bool, default true)

Master switch for the importance-decay job loop. When false, the decay job short-circuits before reading any document — memory importance stops decaying between maintenance runs.

decay_interval_hours (int, default 24)

Minimum hours between decay runs (gated through the lifecycle scheduler). The Settings Basic selector “Freshness speed” writes this key together with importance_decay_rate; set it directly only for a custom cadence.

importance_decay_rate (float, default 0.02)

Per-run multiplier: importance *= (1 - rate), clamped to [0, 1] before being written back. 0.02 means each run multiplies the current value by 0.98.

episode_boundary_hours (int, default 4)

Maximum time gap between adjacent memories before a new episode starts in the episode-grouping job.

episode_min_memories (int, default 3)

Minimum number of memories required to form an episode. Groups whose size is strictly less than this are not assigned an episode_id and stay invisible to the reflection tool (memory_reflect).

Contradiction internals

Controls the recurring pass that flags stored memories opposing each other.

contradiction_detection_enabled (bool, default true)

Master switch for the contradiction-detection job loop. This is one of the five Basic controls; the keys below tune how the pass behaves once enabled.

contradiction_batch_size (int, default 100)

Hard cap on the number of fact memories inspected per contradiction-sweep pass.

contradiction_similarity_threshold (float, default 0.85)

Minimum cosine similarity for a pair of fact memories to be considered for opposition.

contradiction_llm_enabled (bool, default false)

⚠ Cost warning. When true, every contradiction sweep may additionally call an LLM for pairwise NLI between high-similarity candidates — LLM usage grows with candidate-pair volume. The default false keeps the detector heuristic-only (lexical negation and opposite-pair rules). Enable only in a controlled setting.

contradiction_interval_hours (int, default 168)

Minimum hours between contradiction sweeps (one week).

Graph analytics internals

Controls the pass that boosts well-connected memories in the relationship graph.

graph_analytics_enabled (bool, default true)

Master switch for the graph-analytics pass. This is one of the five Basic controls (“Graph insights”).

graph_analytics_top_pct (float, default 0.10)

Fraction of highest-degree nodes boosted by the pass.

graph_analytics_boost (float, default 0.05)

Importance increment applied to boosted nodes.

Retrieval internals

Controls how the context-graph retrieval helper finds and ranks memories.

similarity_weight (float, default 0.5)

importance_weight (float, default 0.3)

recency_weight (float, default 0.2)

The three rerank weights combine in the final score, roughly score = similarity_weight * cosine_similarity + importance_weight * importance + recency_weight * recency. The helper does not enforce normalization; keep the triple summing to 1.0. The Settings Basic preset selector writes these as named points (Balanced 0.5/0.3/0.2, Freshest-first 0.2/0.3/0.5, Importance-first 0.3/0.5/0.2); editing any raw weight flips the preset display to Custom.

graph_max_hops (int, default 2)

Maximum BFS depth from each seed node (0 = seeds only). Larger values give richer context but increase retrieval latency.

graph_neighbors_max (int, default 10)

Maximum neighbors retrieved per seed at each hop.

semantic_limit (int, default 5)

Maximum semantic seed memories retrieved before graph expansion.

semantic_threshold (float, default 0.6)

Minimum similarity for a candidate semantic seed.

Storage & recovery

database_path (str, default neuro_core.db)

Path to the plugin's SQLite domain-store database. Relative values resolve plugin-relative; absolute values are honored verbatim, so existing deployments with an absolute location keep working unchanged.

⚠ Relocation warning. Changing this path relocates where the plugin reads and writes its memory database. Existing data is not moved automatically: memories at the old location stop being served, and a fresh database starts empty. To relocate deliberately, stop memory activity, move the database file to the new location, then update this key.

Manual reboot failsafe

After a framework server restart, graph-panel recovery is normally automatic (the panel retries with a fresh CSRF token on the next call). A deeper manual reboot control lives on the Neuro Core graph panel, beside the Refresh button in the panel header. It deliberately resets the panel's cached CSRF token, rebuilds the graph canvas, and re-runs the current search.

Why it lives on the graph panel and not in Settings: the panel's own script scope is the only place where its cached CSRF token and Cytoscape graph instance can be reset together — the Settings window does not own those objects. Use the manual reboot only if automatic recovery did not happen after a server restart.

Override scopes

All 21 keys resolve through the framework plugin settings chain with per-project and per-agent overrides applied on top of the bundled defaults. The Settings window edits the values for the scope you opened it from; changes take effect for future operations after saving.
